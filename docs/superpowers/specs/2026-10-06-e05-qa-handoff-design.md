## 5. Plan, selection va QA qamrovi

Plan immutable approved baseline criterion setini to‘liq partition qiladi: included va explicit exclusions. Baseline tashqarisidagi mezon bu planda yo‘q; hozirgi project scope o‘zgarsa eski plan current scope completeness da’vosi yo‘q. Included criterionda reviewed definition yoki execution yo‘qligi uni denominator’dan chiqarmaydi. Complete verification uchun ≥1 required definition kerak; yo‘qligi `definition_missing`. Optional tests failed bo‘lsa signal ko‘rinadi, lekin required countga aralashmaydi.

Plan approval, definition review va candidate selection distinct immutable decisions. Definition review requires `qa.plan.manage+qa.source.read`; plan approval/selection requires `qa.plan.manage+qa.read+qa.source.read`. Fixture registration alone cannot approve a plan/test.

Plan version + build + environment explicit authorized human CAS selection bilan current bo‘ladi. Draft/rejected/revoked plan tanlanmaydi; field yoki latest timestamp fallback yo‘q. Selection tuzilganidagi criterion versions va source/review proofs revalidated. O‘zgargan criterion/test-definition/review faqat affected entryni stale/unknown qiladi; approved plan denominator saqlanadi, current scope certainty=`partial/unknown`, current percentage stale entries yo‘qligi haqida da’vo bermaydi. Eski snapshot/selection bo‘yicha history alohida metadata; current sifatida qayta talqin qilinmaydi.

Execution outcome `passed|failed|blocked`. Missing — record yo‘q; stale — derived applicability. Designed/reviewed definition lifecycle, executed — passed/failed completed fact; outcome bilan bitta aralash enumga aylantirilmaydi. Eligible completed execution exact selected plan definition/criterion/build/environment pins, reviewed definition, usable source/actor proof va compatible current versionsni talab qiladi. Blocked attempt saqlanadi, completionga kirmaydi.

FR-070 execution coverage: `distinct included criteria with ≥1 current eligible completed execution / distinct included plan criteria`. Failed execution numeratorga kiradi, failed signal saqlanadi. Ratio pass rate yoki acceptance emas. Qo‘shimcha: per criterion required/optional counts, completed/passed/failed/blocked/missing/stale/unknown; `fully_executed` barcha required tests completed bo‘lsa; `all_required_passed` barcha required tests current passed bo‘lsa. Nol required test ikkala flagni true qilmaydi. Bir pass boshqa blocked/missing/failni yashirmaydi. ## 6. Execution ordering va qayta test

Series `(source_instance, definition_version, build, environment)`. Source execution ID attempt identity; caller expected series revision hamda attempt ordinalni beradi. Yangi lokal synthetic attempt next ordinal bilan CAS; correction same identityning strictly newer source revisioni. Replay same revision/hash returns same record; conflicting identity/hash409. Kech yetib kelgan eski source revision historical record bo‘lib saqlanadi, headni almashtirmaydi. Boshqa source instance series’i avtomatik birlashtirilmaydi: plan exact seriesni tanlaydi; conflicting/unsupported series unknown.

Within one series, retest distinct execution identity/ordinal va same-series predecessor reference talab qiladi; correction retest sonini oshirmaydi. Source counters/ordering gaps yoki missing predecessor completeness gap bo‘lib ko‘rsatiladi; favourable current verification berilmaydi. Build, environment yoki definition o‘zgarsa yangi series boshlanadi; cross-build retest reference uchun old attempt historical origin sifatida separate `retests_execution_id` lineage saqlanadi, current series predecessor deb berilmaydi. No arbitrary source timestamps for ordering. Late original source records carry source ordinal independently of local pointer revision; local recording of a new synthetic retest must use next expected series ordinal, so an arbitrary skipped ordinal cannot assert complete sequence.

## 7. Nuqson va topshirish workflowi

Defect states: `open→triaged→fixed_awaiting_retest→verified_closed`; `verified_closed→reopened→triaged`. Har transition expected defect revision, source evidence va typed reason bilan authorized human CAS. Severity `critical|high|medium|low`; reproducibility `reproduced|not_reproduced|unknown`. Initial build/criterion/definition pins immutable; current affected pins live in each immutable defect event and can change only through explicit reviewed `new_scope` reopening for a verified_closed defect, or a reviewed `scope_revised` event for `open|triaged|fixed_awaiting_retest|reopened`. Scope revision preserves the workflow state and records cause=new_scope; if it was fixed_awaiting_retest, the previous fixed MR/retest request becomes historical and a new explicit fix/retest request under replacement pins is required before closure. That event references the replacement current version of the same stable criterion and test identity, validates the E03 task/criterion linkage and preserves old/new pins plus change evidence. A different unrelated criterion requires a separately linked defect, not silently moving this defect. If the original criterion is removed and no valid replacement linkage exists, current verification is unknown/out_of_scope; it cannot be force-closed with unrelated passing test. Bug description source-safe facts, not employee conclusion.

Fixed state exact synthetic fixing-MR reference bilan inson tomonidan qayd etiladi; MR reference fixning isboti emas. Closure explicit human decision va selected current build/environmentda latest explicitly reviewed affected criterion/definition version uchun eligible passed retestni talab qiladi, exact selection/retest pins saqlanadi. Closure reads the selected series current attempt head and that attempt’s current source-correction head under locks: only that exact latest completed passed attempt can close. Later failed/blocked/unknown or invalid correction forbids fallback to an older pass. The retest must reference this defect’s fix/retest request and its exact current affected pins, not merely any passing test. Failed/blocked retest yopmaydi. New outcome import auto-close qilmaydi. New selection/criterion incompatible bo‘lsa old closure applicability stale; tarix rewrite yoki auto-reopen yo‘q. Current signal eski stale closurega tayanib riskni favourable bermaydi.

Duplicate disposition is separate from defect state: `active|duplicate`; canonical target must already have reviewed triage, and a duplicate disposition never auto-closes this defect.

Reopening uchun human-reviewed cause: `incomplete_fix|new_scope|environment|regression|insufficient_evidence` va evidence reference. Cause defect/contextga tegishli; odamga avtomatik blame yo‘q. Duplicate review canonical defect same project pin, self-link/cycle rad, ikkala tarix saqlanadi; fail natijasi va required test yo‘qolmaydi. Escape-defect ratio release/observation policy yo‘qligi sabab hisoblanmaydi.

Handoff types `verification_blocked|fix_requested|retest_requested|support_requested`; events `opened|acknowledged|resolved|context_added|owner_changed`. Workflow state is `open→acknowledged→resolved`, with explicit evidence-backed `open→resolved` allowed. `context_added` and `owner_changed` preserve open/acknowledged state; context can be appended after resolve without reopening. Resolved is terminal: no late acknowledge/owner change or auto-reopen; a distinct linked handoff starts new work. Resolve exact relevant evidence va human reason bilan CAS; context state’ni almashtirmaydi. Original task version/assignee va occurred_atdagi effective role IDs/revisions/periods snapshot/hash bilan saqlanadi. Supplied employee stable UUID must match event-time membership/approved mapping when a source actor exists. Unknown/missing/overflow historical identity yoki roles `attribution=unknown`; email/ism bilan merge yoki hozirgi owner bilan backfill yo‘q. Explicit new owner event current queue’ni o‘zgartiradi, old responsibility history remains.

Queue age only `age_basis=elapsed_utc`, `elapsed_seconds=max(0,server_clock-opened_at)`; future/inconsistent timestamps unknown. `business_age=null/calendar_unavailable`, workday/hours-productivity labels yo‘q. Reassignment does not restart oldest unresolved handoff age unless a distinct new handoff is created; resolved/acknowledged history retained.

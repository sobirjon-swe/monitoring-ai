# Developer analysis deterministic rules v1

Approved partial E04, `unified-diff-v1` / `developer-taxonomy-v1`, 2026-10-06. Implements observed composition and provenance foundations of FR-060/061, AC-03/11 and approved design §§2/6. These are versioned heuristics, not semantic quality, criterion acceptance, authorship, effort, employee hours or financial allocation. AI interpretation remains unavailable in the application; the frozen parser output has no AI prose field.

## Entry points and trust boundary

`analytics/developer_analysis/parser.py` uses Python stdlib only. `parse_input(envelope: dict) -> dict` validates the strict frozen input shape, hashes, paths and redaction mapping, returns the frozen output shape and enforces output bytes. `analyze_diff(diff: str, files: list[dict], rules_version: str) -> dict` returns composition fields and unbound representative locators for internal callers/tests. `main() -> int` reads bounded UTF-8 JSON from stdin and writes one complete JSON document on success; errors return exit1, empty stdout and fixed `invalid_input` on stderr. Logical paths are never opened. Diff content, injected instructions and code remain text; no subprocess, shell, network, source/build/test execution, imports of source content, database access, model or package provisioning occurs in production parser code.

Server authority and current-source verification remain Laravel responsibilities. Python requires the exact approved analyzer/rule versions, lower-case UUID/SHA values, distinct base/head SHA, unique sorted pins, no extra fields and an input hash over the complete canonical envelope with `input_hash` removed. Canonical JSON sorts object keys recursively, preserves list order, emits compact unescaped Unicode/slashes UTF-8 (including literal U+2028/U+2029), and rejects invalid Unicode/numbers. PHP uses `JSON_UNESCAPED_LINE_TERMINATORS` to match this rule. Snapshot/redaction hashes bind LF-normalized safe diff bytes. Complete output echoes immutable IDs/hashes/pins and never diff content or credentials. The fixtures `canonical-unicode.json`, `contract-input.json` and `contract-output.json` support cross-runtime checks with the actual PHP contract/schema validator.

## Supported syntax and observed totals

Supports Git-wrapped unified patches (`diff --git a/path b/path`) and ordinary `--- a/path`, `+++ b/path` unified patches. Descriptors match old/new headers in original order; null denotes `/dev/null` creation/deletion. Git wrapper paths retain the existing non-null counterpart for new/deleted files. Safe rename headers, index/mode/similarity metadata and exact `\ No newline at end of file` markers are preserved in the hash. Quoted/escaped/space-containing or ambiguous paths are rejected; case-sensitive relative POSIX paths must be at most500 UTF-8 bytes, with no controls, spaces, colon, backslash, absolute prefix or empty/dot/parent segments. Files are never resolved against the host filesystem.

Hunk headers supply cursor positions and required old/new lengths, not totals. Context advances both cursors, `-` old/base and `+` new/head. The parser counts actual changed lines, rejects missing/excess lines, overlapping/backward hunks, invalid coordinates and wrong bound paths. All seven added/deleted buckets are disjoint and sum to observed totals; file counts also sum to totals. Counts never come from source diffstat or declarations. AC-03 uses actual fixture lines: +5172 =3800 generated +900 application +300 tests +100 config +72 docs, vendor/unknown0. Separate −378 =200 generated +100 application +40 tests +20 config +18 docs, vendor/unknown0. This composition says nothing about worked time or accepted progress.

No-hunk Git sections require actual paired metadata rather than an inferred path flag. A bare wrapper, partial old/new mode or partial rename-from/to pair is rejected. Recognized Git file modes are `100644`, `100755`, `120000`, `160000`; duplicate/invalid modes, contradictory creation/deletion binding and unchanged old/new mode declarations are rejected. A verified regular-file permission-only pair (`100644`↔`100755`) yields complete observed zero changed lines. A complete rename pair with `similarity index 100%` establishes a supported text-unchanged rename; other/absent similarity yields partial unsupported/counts_unknown with unresolved patch, preserving the rename metadata without claiming that zero observed lines is full source evidence. File-type mode transitions without text likewise stay partial/counts_unknown. Text hunks still require matching paired file headers and their actual lines.

Text headers cannot be bypassed by a metadata-only shortcut: any `---`/`+++` must form a matching complete pair, and advertised text headers with no actual hunk are rejected conservatively. An optional Git `index oldblob..newblob [mode]` is parsed as exactly one pair of lowercase7–40 hex identifiers and optional recognized mode; malformed/duplicate index declarations reject. Distinct supplied blob identifiers, including differently abbreviated strings, prevent a no-hunk mode/100%-rename section from claiming unchanged content: observed zero remains partial unsupported/counts_unknown and patch unresolved. Identical index identifiers retain a supported true paired mode-only result. Index metadata and text headers remain byte-significant in the patch hash.

Conventional `Binary files … differ` / `GIT binary patch` metadata gives binary/counts_unknown coverage with no decoded binary contents or locators. `diff --cc path` / `diff --combined path` is explicitly unsupported/counts_unknown, with zero observed ordinary changed lines and no locators. Exact unprefixed `[TRUNCATED]` or `... diff truncated ...` marks omitted content; actual lines before it remain observed, incomplete hunk lengths are permitted only with that marker, and coverage adds truncated/counts_unknown. A malformed ordinary hunk or an unmarked incomplete EOF is rejected rather than silently treated as truncated. Input limits are rejected, not represented as successful partial analysis. Unsupported/truncated totals describe only observed supported text; zero does not prove no source changes or remaining work.

## Ordered primary taxonomy

Each observed line uses its own old/new path and the following precedence: generated → vendor → tests → config → docs → application → unknown. Paths and suffixes are case-sensitive; directory checks apply to segments before the basename. Overlap is visible through `mixed`, independent of primary precedence. A file's primary bucket is its new path classification (old path for deletion); an explicit file-wide generated declaration overrides it. Mixed files can contain multiple primary line buckets even though the compact file record carries only one primary file bucket. Aggregate buckets follow line classification, not an assumption that every line inherits the file bucket.

| Bucket | Exact v1 path/declaration rules |
|---|---|
| generated | Directory segment `generated`, `gen`, `dist`, `build`; basename suffix `.generated.py`, `.generated.php`, `.generated.ts`, `.g.cs`, `.min.js`, `.min.css`; or the explicit declarations below |
| vendor | Directory segment `vendor`, `node_modules`, `third_party`, `third-party` |
| tests | Directory segment `tests`, `test`, `__tests__`, `spec`; basename prefix `test_`; suffix `_test.py`, `.test.js`, `.test.ts`, `.spec.js`, `.spec.ts`, `Test.php` |
| config | Directory segment `config`, `configuration`; suffix `.ini`, `.toml`, `.yaml`, `.yml`, `.json`, `.env`; exact basename `Dockerfile`, `Makefile`, `.gitignore` |
| docs | Directory segment `docs`, `documentation`; suffix `.md`, `.rst`, `.txt`, `.adoc` |
| application | Recognized suffix `.py`, `.php`, `.js`, `.ts`, `.jsx`, `.tsx`, `.java`, `.cs`, `.go`, `.rs`, `.c`, `.cpp`, `.h`, `.rb`, `.sql`, `.html`, `.css`, `.vue`, `.svelte` |
| unknown | No recognized candidate; included in counts and adds unknown_path partial coverage |

An exact source line `// @generated`, `# @generated`, `/* @generated */` or `<!-- @generated -->` at source coordinate1 declares that side of a file generated. The same text at another coordinate, inside strings or with extra surrounding words does not declare the file. Exact `// BEGIN GENERATED` / `// END GENERATED`, `# BEGIN GENERATED` / `# END GENERATED` or `<!-- BEGIN GENERATED -->` / `<!-- END GENERATED -->` creates a bounded region independently on each side. Marker lines themselves belong to the generated region. Nested/unmatched regions are rejected, except an explicit truncated region remains partial. Arbitrary nearby text containing “generated” never changes taxonomy. Markers are heuristic evidence and do not establish an actual generator invocation.

Region authority requires contiguous observed coordinates separately on old/new sides, including across adjacent hunks. An unobserved hunk gap while a region is open may contain unseen END/START markers: subsequent affected lines use unknown classification until an observed closing boundary or fresh explicit start, with partial unsupported coverage and unresolved patch. Existing independent file-wide/path-generated evidence can still classify those lines generated, while the uncertain region relation remains disclosed. Known observed counts and valid locators remain conserved; unknown_path reflects an unknown primary classification even on a syntactically known path. A gap does not fabricate counts_unknown when all changed-line observations remain intact. Open regions with a known contiguous boundary but no end still reject; uncertain gap boundaries retain partial facts rather than extrapolating missing source. Contiguous markers retain their generated classification.

Independent flags: `generated` for generated path/declaration/region; `mixed` for overlapping path candidates or more than one observed line bucket; `rename` for distinct non-null paths; `template` for a `templates`/`template` directory or basename containing `template`; `migration` for `migrations`/`migration` directories; binary/unsupported/truncated/redacted flags reflect their coverage states. Template/migration relation does not classify a semantic refactor or prove quality. Review corrections require a new approved rule/snapshot version and rerun; old facts are immutable.

## Redaction, provenance and bounds

`secret-gate-v1` mapping is unique 1-based diff line plus original `+`, `-` or space prefix. Mapped text must exactly equal prefix + `[REDACTED]` in a parsed ordinary hunk; mapping into metadata/binary/unsupported contents, wrong prefix, duplicates or block-v1 mapping is rejected. Redacted facts preserve coordinates/counts, add per-file/global redacted partial coverage and make patch dedupe unresolved. This verifies the gate's coordinate mapping; it does not claim corporate DLP or recover the original secret.

Exact patch hash is SHA256 over UTF-8 diff after **only CRLF→LF**. Order, headers/index metadata, hunk offsets, paths, whitespace and content remain significant. Bare CR is rejected. IDs and SHA pins are echoed separately and never added to patch bytes. Binary/unsupported/truncated/redacted patches have `patch.status=unresolved, hash=null`; different redacted secrets are never proven identical. Unknown taxonomy alone leaves the exact patch-byte group available. The caller must scope exact groups to tenant/project/repository and requirement context; Python has no authority to dedupe across scopes, credit ownership or remove source revisions.

Representatives are the first≤200 actual changed lines in file/hunk order. Deleted locators reference old path/base SHA and added locators new path/head SHA; hunk_index is zero-based over the whole patch. Full output binds each to snapshot ID/hash and both SHAs. `omitted_locator_count` explicitly counts further parsed changed-line locators. Aggregate counts remain conserved when representatives are omitted. Binary/unsupported files have no representatives. Publication must independently validate all bindings against authorized input.

Enforced development bounds: diff524288 UTF-8 bytes; input1048576 bytes; files100; hunks2000; total observed added+deleted50000; representative locators200; source coordinates1–2147483647; stdout262144 bytes including newline. Overflow fails before writing any result; no byte-truncated JSON. Stdlib unit tests and parser CLI checks do not prove AppContainer isolation, memory/CPU/wall enforcement or production capacity. The runner remains disabled until its separately reviewed OS activation gate passes.

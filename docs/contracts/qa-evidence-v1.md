This deterministic Laravel/PostgreSQL slice implements part of FR-070/E05-BE/DATA/QA and AC-08/09/18. Full E05/AC-07 and production QA policy remain open. All examples and registered sources are synthetic; AI interpretation is `unavailable`.

## Transport and authority

Base `/api/v1/projects/{project}/qa`. UUID routes and loopback local bearer authentication supply trusted tenant/requester/project; unknown authority fields never override them. Each service rechecks exact current project membership, policy, purpose and source access under project serialization and actual final PostgreSQL clock. Tenant grants or role titles alone confer no QA access. `qa.department.read` is a separately authorized department scope in addition to project `qa.read` + `qa.source.read`.

POST body: UTF-8 root JSON object, at most65536 bytes, nesting depth16. Duplicate decoded keys at any depth (including escaped aliases), control bytes, unknown fields, bool/integer and array/object substitutions are rejected. Empty object `{}` remains an object through transport until service schema validation; it is not interchangeable with `[]`. Text bounds are UTF-8 **bytes**: title500; steps/expected result/reproduction/blocked reason4000; nonblank human/exclusion reason2000. Common credential scanning precedes persistence; this is not corporate DLP. No raw body, proof, source secret or traceback is returned/logged. POST accepts no query fields. GET/HEAD accept no body; unknown query fields are rejected.

They control local source/series heads and are **outside** immutable envelope hashes. Human review/selection/event `expected_revision` is inside its strict body instead. R4 initial defect/handoff envelopes do not expose a generalized source-correction API.

Tenant and requester are never envelope fields. `received_at` is server DB time. Source revision/attempt ordinal, local source-head/series CAS revision, and human review/event revision are distinct counters. Handoff envelope/body occurred_at must match. ## Canonical identity and history

Envelope hash is SHA256 of recursively sorted object keys, ordered arrays, unescaped UTF-8 Unicode/slashes/line terminators. No self hash field exists in the envelope. Natural identity is tenant/project/source instance/object/source revision. Request identity additionally includes requester/typed operation/key; equal keys on different operations are distinct. A same-identity different hash conflicts409. Exact replay rechecks authority and durable terminal applicability inside the same project transaction before returning/binding a natural alias. It adds no attempt/fact/audit/outbox. New aliases may add only their request binding.

Definition content hash covers its exact immutable body. Plan-entry hash covers baseline/policy/item/stable criterion/version, included/exclusion reason, and tests sorted by definition UUID with exact definition hash, original definition-review ID/subject hash, source instance, required and release-critical flag. Plan hash covers baseline ID/hash/policy plus full entries sorted by stable criterion; each entry contains its immutable snapshot UUID and complete content. It is not a hash of the compact UUID list. Entry/plan DTO self fields are excluded. At most100 criteria,20 definitions per criterion,2000 total; compose sends at most100 immutable entry UUIDs, preserving the64KiB limit without weakening the assembled hash.

Definition review is reviewed/rejected/revoked; plan review approved/rejected/revoked. New versions inherit no review. Selection explicitly pins exact approved plan review/build/environment; importing a build does not select it. Revoked/replaced original grant or review cannot be repaired by replacement current authorization. Observed terminal invalidity survives exact restoration and blocks retained/natural-alias replay; wholly unobserved revoke/restore remains a disclosed limitation.

Execution series is exact source/definition/build/environment. New attempts use next ordinal and same-series predecessor; corrections retain identity and advance source version without adding an attempt. Historical cross-build origin is separate `retests_execution_id`. Latest known attempt and its latest correction govern current outcome even when invalid; no older-pass fallback. Source/order/predecessor gaps remain partial/unknown. Defect closure requires the latest exact passed request-bound retest under current affected task/criterion/definition/selection/build/environment pins plus explicit human CAS. Context/duplicate events preserve the newest request boundary; scope/reopen/new fix request supersede it. Source import never auto-closes or approves release.

## Read DTO and paging

Project verification returns `qa_verification`, `selection`, `counts`, `critical_signals`, `coverage_status`, `reason_codes`, `synthetic:true`, `ai_interpretation:"unavailable"`. Numerator is distinct included criteria with at least one current completed passed **or failed** execution; denominator is distinct approved included criteria. Ratio basis points is floor(10000*numerator/denominator), null for absent/zero/unknown denominator. Blocked/missing/stale/unknown do not complete a criterion. Fully executed/all-required-passed require at least one required definition and every required outcome; optional critical failures remain visible. No-plan null and approved zero included scope are distinct. Denominator/history survives scope changes; observed arithmetic is not release approval, pass rate, E03 accepted progress or employee score.

Department verification withholds global selection/build/environment/plan/coverage/completion/excluded/omitted fields; basis is `department_authorized_entries`. Global counts/ratio/completion and per-criterion completion flags are null. Only permitted tests/status counts and critical failures are delivered, after all named source/review/event-time assignee/owner and linked dependencies pass current department membership. Missing global prerequisites remain unknown with uniform `current_verification_unavailable`; hidden actor/grant reasons and counts are withheld. Queue additionally checks the current definition-review employee; immutable history retains its original proof semantics.

Current critical defects are inventoried separately from selected execution attempts. At most 100 authorized critical roots are evaluated, including their bounded canonical and evidence dependencies; department visibility is applied before that limit and rechecked under coordination. An unresolved applicable defect emits `critical_defect_unresolved` even when its selected test passes. Missing/stale proof or scope, an old selection-bound closure, or unresolved canonical clearance emits `critical_defect_applicability_unknown` and unknown coverage. An applicable human closure requires the current selected passing execution, its exact fix request and valid original/current/terminal dependencies. Historical closure or duplicate disposition alone never clears current risk. Initial report execution lineage remains part of department visibility but its old registrar authority does not substitute for or block a fresh applicable retest. This does not change E03 accepted weight.

`critical_signals` always contains `codes`, at most 100 `items`, `omitted_count` and `continuation_required`. Omission counts describe only evaluated authorized signals; department metadata is rebuilt solely from visible tests/defects. If the defect inventory/dependency bound prevents complete evaluation, coverage is unknown and `continuation_required=true`; an exact omitted total is not inferred. No favorable subset or hidden global count is returned. History/queue original-authority expansion over 100 actors likewise returns an empty unknown page with `coverage_limit`, null count/cursor and no terminal revocation caused by that uncertainty. Smaller legal pages can remain complete.

Manual closure, handoff transition and mandatory execution dependencies overlay persisted terminal applicability before consuming original proofs. Restoring the exact grant row does not revive observed invalid evidence. Fresh retests retain optional immutable predecessor lineage independently of that predecessor's revoked authority. Responsibility snapshots use the requested task version's `[effective_at,next_revision.effective_at)` interval, established in the prelocked authority phase with bounded exact successor/head reads; unavailable interval evidence stays unknown. Late facts inside the original interval keep the original assignee; no current-assignee substitution occurs.

History kinds: build/environment/definition/plan/selection/execution/defect/handoff. History and queue return bounded `items`, `next_cursor`, `visible_record_count`, coverage/reasons and synthetic/AI markers. Default50/max100, cursor≤128 ASCII bytes. History is ascending immutable revision; queue is ascending UTC opened_at microseconds/UUID. Opaque base64url HMAC cursor binds tenant/requester/project/resource/subject/department. Each page rechecks authority and scoped heads; revoked access denies the next page. Filtering happens before LIMIT/count/continuation; overflow is wholly unknown without hidden counts or IDs.

Queue records retain event-time responsibility and separate explicit current owner. Age is elapsed UTC seconds; business_age=null/calendar_unavailable. Future/inconsistent dates and missing historical identity remain unknown, not inferred hours or blame. Closed project current verification unavailable; authorized metadata history remains accessible. No export/cache/notification endpoint or live connector is included.

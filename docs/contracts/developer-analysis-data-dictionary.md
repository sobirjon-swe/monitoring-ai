# Developer analysis data dictionary v1

2026-10-06. Approved partial E04: FR-060/061/120 deterministic foundation, FR-200, §25, AC-03/11. Storage migrations `000015`–`000018`; [JSON/authority contract](developer-analysis-v1.md), [taxonomy](developer-analysis-rules-v1.md), [OpenAPI1.3.0](../api/openapi.yaml). Actual parser runtime remains disabled; this dictionary describes implemented storage, not activated end-to-end analysis or full E04.

All nine tables carry trusted `tenant_id` and `project_id`, FORCE RLS and composite references. Runtime is nonowner/non-SUPERUSER/non-BYPASSRLS. Transaction-local tenant context restores after nested calls. Python has no DB credentials. All DELETE/TRUNCATE are denied; immutable tables also deny runtime UPDATE. Corrections append new snapshots/runs/reviews, never overwrite historical facts.

| Table | Meaning and invariant |
|---|---|
| `developer_snapshots` | Immutable approved synthetic source instance/repository/MR/ordinal; distinct40-hex base/head SHA, source status open/merged/released, safe LF diff≤524288 bytes, content SHA256, paths≤100, versioned redaction mapping, actor, occurred/received/source_updated/registered UTC times. Logical SHA/path is not a verified Git commit or URL. |
| `developer_source_heads` | One current snapshot per scoped natural source key. Separate integer CAS revision; ordinal must advance. Snapshot FK binds exact source/ordinal. Late events cannot replace current. |
| `developer_source_events` | Immutable every accepted/blocked receipt. Scoped source/ordinal/payload SHA256 uniqueness. Approved binds snapshot; blocked has null snapshot and safe `secret_blocked`/`invalid_diff`, without raw secret. Newer blocked receipt can invalidate an older safe head. |
| `developer_runs` | Immutable request ID, requester, snapshot, normalized criterion/task version pins, canonical input/hash and exact original authority/hash/capture time. Unique tenant/requester/operation/idempotency key. Mutable status, applicability, bounded attempt count, lease token/expiry, completion time and fixed reason only. Observed stale is terminal even after authority/source restore. |
| `developer_results` | One immutable validated result per run, composite tenant/project/snapshot/run/input binding. Bounded canonical output/hash and exact claimed processing authority/hash, published time. Stale result persists but delivery hides output. |
| `developer_findings` | Exactly one of composition_fact/coverage_notice/provenance_notice per run. Immutable server facts and summary; only review revision/disposition/current-review pointer advances. Pointer FK binds same finding/revision/history row. |
| `developer_reviews` | Immutable UUID, finding, monotonically increasing revision, decision, resulting disposition, authenticated actor, safe reason and actual PostgreSQL `effective_at`. Unique scoped finding/revision. Decision verified/rejected/context-added; context-added retains prior pending/verified/rejected disposition. Reason nonblank≤2000 UTF-8 bytes in application before scanner/audit (DB varchar cap is characters). |
| `developer_invalidations` | One immutable observed source_changed/pins_changed/access_revoked/project_closed record per run. Actor/time and optional scoped64-hex event key. Null legacy keys remain intact. This is conservative maintenance, not a grant of content access. |
| `developer_outbox` | Exactly one source-event/run/invalidation reference; only run rows execute analysis. Status pending/processing/retry/completed/dead_letter/blocked, attempts0–5, available_at, lease/completion, safe reason. Execution claims store bounded≤32768-byte processing authority/hash pair; insert cannot fabricate proof, one active lease cannot replace it, source/invalidation rows never carry proof. Legacy null claim proof is preserved until safe expiry/reclaim. |

Versions: `developer-analysis-input-v1`, `developer-analysis-output-v1`, `developer-authority-v1`, `unified-diff-v1`, `developer-taxonomy-v1`, `secret-gate-v1`; policies `block-v1` and explicit fixture-only `redact-lines-v1`. Canonical UTF-8 JSON/hashes preserve ordered lists, sort object keys and match PHP/Python Unicode semantics. Input and processing proofs stay server-only; no raw diff/credentials/proofs in HTTP DTOs or logs.

Finding facts separate three confidence labels and reasons: source=`synthetic_registered` (immutable safe snapshot, SHA not verified in Git); link=`snapshot_bound` (validated logical coordinates, no criterion acceptance); claim=`deterministic_observation` (independently reconstructed counts, partial/supported observation). These are not calibrated probabilities. Facts also carry informational severity, immutable run/request/input/snapshot/hash/SHA/pin/analyzer/rule/output-contract references, assumptions, suggested human validation and counterevidence. AI interpretation is unavailable. Representative locators≤200 preserve old/base deleted versus new/head added; omitted count is explicit.

Seven disjoint primary buckets preserve separate added/deleted totals: generated/vendor/application/tests/config/docs/unknown. Example AC-03: added5172=3800 generated+900 application+300 tests+100 config+72 docs; deleted378=200+100+40+20+18 respectively. Mixed/generated-region/template/migration/rename/binary/unsupported/truncated/redacted flags are independent. Zero observed count with incomplete coverage does not prove zero source work.

`patch.hash` covers exact safe UTF-8/LF bytes, retaining headers/index/mode/hunk positions/file ordering/whitespace. Server `patch_group_id` binds hash plus tenant/project/source-instance/repository and exact criterion/task context. It is metadata only: events/snapshots/runs/results remain distinct; there is no accepted-release/contribution aggregate or authorship claim. Conservative metadata differences cause false negatives. Redacted/binary/truncated/unsupported equivalence remains unresolved/null group.

GET finding delivers ascending revision keyset history default50/max100, `{items,next_cursor}`. Cursor≤128 canonical base64url encodes finding ID/last revision and must match an existing row. Unknown/foreign cursor422; authorization recaptured for every page. Later concurrent appends appear on later pages without changing earlier rows. Reads never freeze or redact-write historical reasons. Current run `verified_findings` contains only up to3 current verified analysis summaries; pending/rejected/stale are excluded. Verification is not E03 acceptance, release attribution or money.

Review coordinates project/state → current viewer read/source/review plus exact original requester proof batch → source/run observations → finding lock/CAS. Final actual-clock effective-period recheck rolls back writes after authority expiry. New reviews on closed projects409; authorized historical metadata remains readable. Stale→verified never rehabilitates facts/applicability. No source records, immutable taxonomy facts or E03 acceptance/progress are rewritten.

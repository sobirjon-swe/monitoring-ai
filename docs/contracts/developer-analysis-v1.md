# Developer analysis v1

Approved partial E04 (FR-060/061 deterministic foundation, AC-03/11). Input and output schemas in this directory are strict local contracts. No worker authority credentials, arbitrary prose, source network or model execution. AI interpretation is unavailable. Schemas use no remote references.

Canonical JSON recursively sorts object keys by string order, preserves ordered lists, uses UTF-8 unescaped Unicode/slashes and no whitespace. SHA256 is lowercase hex. `input_hash` hashes the complete canonical input envelope with only `input_hash` removed. Snapshot hash and redaction hash bind approved LF-normalized safe diff bytes. Request payload hash is separate and excludes worker output and authority. IDs are lowercase UUIDs. Pins are deduplicated/sorted by the requesting server. Immutable source IDs are synthetic logical identifiers, not URLs or checkout instructions.

Input includes run/request UUIDs, safe snapshot, explicit old/new path descriptors, original synthetic SHA/source/revision identifiers, immutable criterion/task version UUID arrays and exact analyzer/rule/redaction versions. Output echoes run/request/input hash, snapshot ID/hash/base/head, pins, analyzer/rule version and redaction version/hash. Output never echoes the diff or authority.

Output counts and each of the seven primary buckets have separate added/deleted counts. Files retain old/new logical paths, primary bucket, counts, coverage and independent flags. Coverage notices are bounded reason codes. `locators` contains at most200 representative added/deleted line records (deleted=old/base; added=new/head), with explicit omitted count. All counts include unknown. Snapshot/path/line/hunk bindings and count conservation are revalidated by the publisher against authorized input. `patch.status=exact` requires a SHA256 over exact safe LF diff bytes; redacted/binary/unsupported/truncated is unresolved with null hash. No semantic equivalence or authorship inference.

Limits: UTF-8 diff524288 bytes, input JSON1048576 bytes, files100, hunks2000, changed lines50000, output JSON262144 bytes, stderr8192 bytes. A valid larger document is rejected, never byte-truncated. Path identifiers are relative case-sensitive POSIX paths with no control/space/backslash/colon, absolute prefix, empty, dot or parent segments. Null old/new denotes creation/deletion, never a filesystem read.

`secret-gate-v1` supports `block-v1` (default) and explicit fixture-only `redact-lines-v1`. Redacted line content becomes `[REDACTED]`, preserving diff prefix and newline count; mapping records1-based diff line and original prefix. Headers/private-key multiline material are blocked. This scanner is a bounded synthetic baseline, not corporate DLP. Rejected events retain safe reason and restricted hash metadata only.

Authority remains Laravel-only. `DeveloperCoordination::run` locks project/state then batch-captures all requester/operator proofs before source/run/outbox/finding locks. Proofs bind exact user employee, membership ID/revision/effective period, grant IDs/revisions/purposes/effective periods and policy ID/version. Shared locks block row revocation until transaction completion; replacement grants cannot repair pinned proofs. Sample time comes from PostgreSQL clock_timestamp after all authority locks. No lifecycle generation mutation. Observed invalidation is terminal for that run.

HTTP paths use existing `/api/v1` convention; design logical `/api/...` is normalized to `/api/v1/...`, without an unversioned alias.

Batch requests are `{actor_id,purposes,pinned_proof?}` and results are a sorted map keyed actor ID. Duplicate actor requests union their purposes before any row acquisition. A pinned proof may cover an original subset of the union; those exact membership/grant/policy references are checked while held and preferred over any replacement grant. The returned proof describes the union at the new actual capture time. The original requester proof remains a separate immutable run input. This supports an operator who is also the requester without losing the original subset.

After batch capture, the callback receives `proofs` and authority acquisition is closed for that transaction phase. Supply requester pinned proof in `authorityRequests` before source/run/outbox locks; do not call capture/valid from the callback. Membership/grant/policy locks are explicit separate ordered queries. Analysis grants are project-only; tenant/department grants do not satisfy the six purposes.

`DeveloperAuthority::assertEffective(array $proofs,string $instant): void` is a pure period check over captured membership/grant rows, with no database queries or new row locks; ineffective proof raises403. Coordination samples clock_timestamp again after the callback and applies it before commit, rolling back callback writes when authority expires during work. R5 may use the same method with a fresh trusted DB instant at its publication boundary. Shared row locks still protect status/revocation; natural time expiry requires this final period check.

Runs initially insert `status=queued,attempt_count=0`, outbox initially `pending,attempt_count=0`. Outbox has exactly one of source_event_id/run_id/invalidation_id; source receipt and invalidation delivery are distinct from execution outbox. Rejected receipts have no snapshot/run, and must never dispatch analysis. Claim updates execution outbox→processing and run→running, increments each attempt by one, sets the same fencing token and60-second expiry in one transaction. Changing an active token requires the next bounded attempt. Nonactive states have both lease fields null. Retry clears both leases, sets outbox retry with5/30/120/600 delay and run queued without another attempt increment. Publication inserts one immutable result per run, bound through tenant/project/snapshot/run/input-hash FK, then sets run succeeded/partial and outbox completed, timestamps completion and clears leases atomically. Permanent failure sets run error and outbox dead_letter; authority/source/pin invalidation sets applicability stale (sticky), may cancel pending/running execution, and blocks outbox. Existing terminal run status/execution fields cannot be restarted. No status or attempt synchronization is inferred outside these processor transactions.

DB tables: snapshots preserve safe_diff/content_hash/paths/redaction and all three source times; source heads bind natural source IDs and ordinal to snapshot, with independent CAS revision. Events retain each source receipt/hash; approved events bind exact snapshot/source ordinal, blocked events have null snapshot and safe reason. Runs retain input/pins/requester proof separate from mutable status/applicability/lease. Results retain output and operator proof. Finding facts are immutable; only review_revision/disposition/current_review_id advances against append-only review history. Context-added must retain existing disposition. Invalidations are append-only and unique per run. All nine tables use FORCE RLS and tenant/project composite references; runtime lacks history UPDATE/DELETE and all table DELETE/TRUNCATE.

Unsupported path limitation: quoted Git paths, whitespace-bearing paths, drive/URI/backslash paths and ambiguous markers are rejected by this conservative synthetic admission gate. They are not claimed to be supported or assigned fabricated locators. Binary/unsupported/truncated metadata within accepted simple logical paths is represented as partial coverage by the parser. Scanner matching common credential assignments is conservative and may reject harmless examples.

## Durable processing authority and human review transport

Incremental migration18 adds nullable legacy-compatible processing_authority/hash to execution outbox. Claim stores the exact captured operator union proof/hash≤32768 bytes with its lease before computation. New lease requires proof; replacement within one lease or proof on source/invalidation rows is denied. Publication compares current substantive exact proof (fresh captured_at excluded for comparison only), then copies the original durable claim proof/hash exactly to immutable result. Original requester remains pinned separately. No proof refresh or authority locks inside the closed callback.

OpenAPI1.3.0 uses POST `/api/v1/findings/{finding}/reviews` with only `{expected_revision,decision,reason}`. Revision integer0–2147483646, decision verified/rejected/context-added; reason valid UTF-8, nonblank,≤2000 bytes bounded before SecretGate and AuditWriter. Duplicate keys/NUL/unknown fields/query parameters/type ambiguity rejected. Current read+source+review and exact original requester proof are one pre-callback batch; callback observes current source/pins without reacquiring authority. Final actual-clock check prevents natural expiry during work from committing. Append history/pointer CAS/audit atomic, competing same revision409. Response includes finding/run/review ID, updated review_revision/disposition/applicability and actual PostgreSQL effective_at. Context retains prior disposition, stale stays stale, closed new review409.

GET finding adds review_history `{items,next_cursor}` default50/max100. Items are immutable id/revision/decision/disposition/actor_id/safe reason/effective_at; ascending revision keyset. Cursor≤128 canonical base64url finding-ID/last-revision binding; existing revision required. Unknown/foreign cursor sanitized422; authorization rechecked before every page. Appends may appear on later pages; no full-history snapshot claim or read-side redaction rewrite. Authorized closed/stale historical metadata remains, while stale/unknown facts/summary are null. Run adds bounded verified_findings of current verified analysis summaries only; pending/rejected/stale excluded. No E03 acceptance/accepted-release/contribution projection.

Observed delivery invalidation may append invalidation/outbox and update run status/applicability; GET never changes immutable source/facts/review rows. First observation reloads newly updated run status/reason coherently. Denied exact authority refreshes only the hinted run after rollback, with open authority phase and no content return.

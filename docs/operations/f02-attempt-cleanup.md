# F02 attempt secret cleanup (local development)

This is an incomplete, unreviewed F02 implementation. The cleanup command scans only tenant UUIDs explicitly listed in `browser.attempt_cleanup_tenants`; the default list is empty. It examines at most 100 active attempts per configured tenant per invocation, storing a tenant-scoped cursor and fixed sweep high-water in PostgreSQL. New lower IDs are visited after the sweep wraps, and later higher IDs cannot extend the current sweep indefinitely. Cursor advancement and the batch share a transaction, so an interrupted batch can be retried.

The Laravel schedule invokes `browser:cleanup-attempts` every minute when the scheduler is running. For local development, the operator must run `php artisan schedule:work` using the project's configured PHP executable. If the scheduler is stopped or a tenant is not listed, no periodic cleanup occurs. This does not authorize a production scheduler or deployment.

Global session fence rows are retained; bounded fence cleanup, physical-commit concurrency and independent security review remain open. The cleanup checks global and tenant fences, attempt expiry, current tenant and actor status, the encrypted session binding, and current BA authority and original evidence through the domain authorization path. A conclusive denial clears ciphertext; an infrastructure or incomplete-coverage error leaves the batch for retry. No claim of complete or timely deletion is made while the scheduler is unavailable or the allowlist is empty. The allowlist stays empty until an explicitly approved synthetic workspace is provisioned and its tenant is configured; it must not be broadened to other tenants.
